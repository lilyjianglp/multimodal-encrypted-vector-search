# SIFT1M 私有近邻检索对比审计

测试日期：2026-08-29。数据集为 ANN-Benchmarks SIFT1M：1,000,000 条 128 维向量、10,000 条查询和官方精确近邻标签。

## 1. 召回与候选量

使用 Faiss IVFFlat，`nlist=1024`、25 轮聚类、一次训练：

| 候选策略 | 参数 | Recall@10 | 候选量 |
| --- | --- | ---: | ---: |
| 完整倒排簇 | `nprobe=12` | 89.533% | 平均 13,108 |
| 完整倒排簇 | `nprobe=13` | 90.545% | 平均 14,178 |
| 完整倒排簇 | `nprobe=16` | 92.864% | 平均 17,358 |
| 每簇固定 Top-R | `nprobe=32, R=512` | 64.675% | 最多 16,384 |
| 每簇固定 Top-R | `nprobe=32, R=1024` | 89.312% | 最多 32,768 |
| 每簇固定 Top-R | `nprobe=16, R=1536` | 90.790% | 最多 24,576 |

完整倒排簇的最小实测 90% 配置是 `nprobe=13`。在已测固定截断组合中，候选上限最小且超过 90% 的配置是 `nprobe=16, R=1536`。

生产索引服务按照向量到所属簇心的距离预先排序，每簇仅返回固定 Top-R。这个排序与查询无关，能避免服务器直接看到查询，但它会丢弃靠近簇边界的近邻。因此不能把完整 IVFFlat 的 17,358 个扫描候选和默认网关 `32 × 512` 的候选当成同一种召回路径。

## 2. CKKS 核心实测

参数：Microsoft SEAL 4.1.2、CKKS、`poly_modulus_degree=8192`、系数模数位数 `[60,40,40,60]`、`scale=2^40`。SIFT 的 L2 排名通过增广内积精确转换到 512 维计算。

16 个候选、10 条查询的完整 512 维结果：

| 指标 | 实测值 |
| --- | ---: |
| HE 服务计算 | 1.921 s/query |
| 本地墙钟时间（含编码、加解密） | 2.804 s/query |
| 查询密文 | 393,329 B（0.375 MiB） |
| 返回密文 | 3,146,632 B（3.001 MiB） |
| 平均绝对分数误差 | 4.712e-7 |
| Top-10 集合一致率（10 条查询） | 100% |

现有正确性路径每个密文只在槽位 `0,512,...,3584` 放置 8 个候选。对连续 4096 槽布局进行实测后发现，原布局只有 8/4096 个槽的误差小于 `1e-4`，Top-10 Recall 仅 10%。原因是对角线明文使用了 `x_s[diag]`，而重复查询布局要求使用 `x_s[(s+diag) mod 512]`。

在基准程序中修正该索引后，4096/4096 个槽的误差均小于 `1e-4`，单个 4096 候选包得到：HE 计算 1.057 秒、本地墙钟 1.389 秒、在线密文通信 1.88 MiB、Top-10 Recall 100%。

### 固定候选功能端到端测试

固定候选配置 `nprobe=16、R=1536` 每条查询最多产生：

\[
16\times1536=24,576
\]

个候选。连续槽对角打包每个候选包并行处理 4,096 个候选，因此需要：

\[
24,576/4,096=6
\]

个候选包。

当前完整组级 BSGS 版本对 10 条查询的平均结果为：

| 指标 | 当前结果 |
| --- | ---: |
| 候选数量 | 24,576/query |
| 候选包数量 | 6/query |
| 10 条查询平均明文 Recall@10 | 92.0% |
| 10 条查询平均 CKKS Recall@10 | 92.0% |
| CKKS/明文 Top-10 集合一致率 | 100% |
| CKKS/明文 Top-10 顺序一致率 | 100% |
| CKKS 核心计算 | 1.202 s/query |
| 本地功能端到端延迟 | 7.612 s/query |
| 在线密文通信 | 9.38 MiB/query |
| 密文旋转 | 276 次/query |
| 密文—明文乘法 | 3,072 次/query |
| 平均绝对分数误差 | 2.06e-8 |

其中，276 次旋转来自 6 个候选包乘以每包 46 次旋转；3,072 次密文—明文乘法来自 6 个候选包乘以每包 512 次乘法。

这里的“本地功能端到端”包括客户端加密、基准程序在线构造和编码对角明文、密态计算、客户端解密以及本地 Top-10，但没有经过真实 Gateway、Index 和网络进程，也没有加入伪簇。因此，7.612 秒不能作为生产网络端到端延迟；其中较多时间来自基准程序在线生成和编码 3,072 条对角明文。生产路径会离线预生成 `.dia` 文件，不承担这部分在线编码成本。

全量 10,000 条查询的明文固定候选覆盖率为 90.790%；这里的 10 条 CKKS 查询用于验证密态评分不会进一步降低召回。客户端仍会得到并解密全部候选分数，因此该测试也不等价于只泄露最终 Top-10 的安全 Top-k 协议。

完整组级 BSGS 的具体做法是：离线生成器先把第 `r=32g+b` 条对角明文反向预旋转 `32g`；在线阶段缓存 32 个 Baby 密文旋转，在每个 Giant 组内完成 32 条对角线的乘加，最后只对组部分和执行一次 Giant 旋转。这样每个 4096 候选包的非零旋转由 511 次降到 `31+15=46` 次，密文—明文乘法仍为 512 次。

| 相同工作负载 | 旧直接对角法 | 完整组级 BSGS | 结果 |
| --- | ---: | ---: | ---: |
| 单包旋转 / 明文乘法 | 511 / 512 | 46 / 512 | 旋转减少 91.0% |
| 4096 候选 HE 核心 | 0.961 s | 0.205 s | 4.69× |
| 24,576 候选、10 查询 HE 核心均值 | 6.016 s/query | 1.202 s/query | 5.00× |
| 24,576 候选本地功能墙钟均值 | 7.918 s/query | 7.612 s/query | 1.04× |

本地功能墙钟提升小于 HE 核心，是因为该基准仍在线构造并编码 3,072 条对角明文；生产链路使用离线预生成的 `.dia` 文件，不承担这部分在线编码成本。10 条 BSGS 查询的 CKKS/明文 Top-10 集合及顺序均完全一致，平均绝对分数误差为 `2.06e-8`。

生产生成器回写连续槽修复、重建对角块后，又通过真实的客户端 → Gateway → Index → HECompute → Gateway → 客户端网络进程链路完成了一条 SIFT1M 查询。配置为 16 个真簇、16 个数字诱饵簇、每簇固定 Top-1536，共 49,152 个槽和 48 个返回密文：

| 指标 | 单查询实测 |
| --- | ---: |
| 候选覆盖 Recall@10 | 100% |
| CKKS 端到端 Recall@10 | 100% |
| CKKS/明文 Top-10 集合与顺序 | 100% / 完全一致 |
| 真实候选平均/最大绝对分数误差 | 4.20e-8 / 1.40e-6 |
| HE 核心遥测 | 3.161 s；552 次旋转；6,144 次明文乘法 |
| Gateway / 客户端墙钟 | 9.327 s / 9.399 s |
| 查询请求 / 密文响应 | 393,545 B / 18,879,840 B |
| 查询在线载荷合计 | 19,273,385 B（18.38 MiB） |
| 一次性 Galois + Relin 评估密钥 | 39,395,731 B（37.57 MiB） |

生产遥测中的 552 次旋转正好等于 12 个候选包乘以每包 46 次；6,144 次乘法等于 12 包乘以每包 512 次。与同配置旧生产链路的客户端墙钟 17.538 秒相比，新版为 9.399 秒，端到端约 1.87×；通信量和响应密文数量保持不变。该单查询用于确认生产网络链路和槽位映射正确，不能代替多查询延迟分布或全量端到端 Recall 统计。完整结果见 `results/sift1m/network_e2e_full_bsgs_metrics.json`（结果目录默认被 Git 忽略）。

修正布局之前，按已经验证的 8 路打包实现线性外推为：

| 候选方案 | HE 计算估计 | 返回密文估计 |
| --- | ---: | ---: |
| 完整簇 `nprobe=13`，平均 14,178 条 | 约 28.4 min | 约 2.60 GiB |
| 固定 Top-R `nprobe=16,R=1536`，24,576 条 | 约 49.2 min | 约 4.50 GiB |

这些是旧 8 路布局的工程外推，仅用于说明 SIMD 修正的必要性，不应再作为修正后系统的性能结果。

## 4. 当前不能宣称的结论

不能根据 `nprobe=16` 的明文 IVFFlat Recall@10=92.864%，宣称本项目的完整私有检索召回率或综合性能超过 SANNS/PANTHER，原因包括：

1. 该召回率在服务器可见明文查询的 Faiss 路径上测得；
2. 16 候选 CKKS 测试先用明文查询筛选候选，只验证密态分数精度；
3. 当前默认固定 Top-R 候选路径在 SIFT1M 上只有 64.675%；调参到 `nprobe=16,R=1536` 后为 90.790%；
4. 连续 4096 槽修复与完整组级 BSGS 已回写生产生成器并通过真实网络进程链路验证，但目前只有一条网络查询，尚不足以给出稳定的端到端统计；
5. 数字诱饵使 Gateway/Index 无法从 ID 格式直接区分真簇和假簇，但服务端仍可观察 32 个混合簇 ID、重复会话模式和候选访问；这不是 PIR/ORAM，安全模型弱于 SANNS/PANTHER 的“除最终结果外不泄露”目标；
6. 当前客户端会解密候选分数，尚缺少安全 Top-k，不能直接对齐两篇论文的完整协议。

可严谨宣称的是：本项目已在 SIFT1M 上跑通连续槽对角打包和完整组级 BSGS 的客户端加密—Gateway/Index 候选读取—HECompute 密态评分—客户端解密 Top-k 真实网络链路；每个 4096 候选包的在线旋转由 511 次降到 46 次，旋转复杂度由 `O(d)` 降到 `O(√d)`，匹配工作负载的 HE 核心加速约 5×；固定候选配置在全量明文评估中达到 90% 以上 Recall@10，且已测 CKKS 查询没有造成额外召回损失。下一步仍需进行多查询网络统计并加入安全 Top-k，之后才能按 SANNS/PANTHER 的安全模型进行完整协议比较。
